# PRD - 智能视频精彩片段提取系统

## 一、项目概述

### 1.1 项目背景
数字媒体内容团队每天会处理大量游戏录屏、场景演示、宣传素材和用户投稿内容。仅依靠人工逐段观看视频，会产生以下问题：
- 长视频中很难快速定位角色、战斗、道具和重要场景；
- 内容审核结果缺乏统一标准，无法追溯具体证据；
- 任务处理过程没有任务编号和状态记录；
- 视频、关键帧、检测结果和测试资料容易分散；
- 交付时缺少统一的文件命名、报告和验收依据。

### 1.2 项目目标
开发一个轻量级 CV 工作台，利用目标检测、画面变化和运动强度，自动找出值得人工复核的关键帧和候选片段。

### 1.3 项目方向
方向 B：智能视频精彩片段提取系统

## 三、核心功能需求

### 3.1 必须实现的功能

| 序号 | 功能 | 描述 | 验收标准 |
|---|---|---|---|
| 1 | 视频上传 | 支持上传游戏录屏或场景演示视频 | 支持 mp4、mov、avi、mkv、webm 格式 |
| 2 | 任务创建 | 创建任务并返回任务编号 | 返回 201，包含 job 对象 |
| 3 | 视频采样 | 使用 OpenCV 按时间间隔读取视频帧 | 采样间隔可配置，默认 15 帧 |
| 4 | 目标检测 | 使用 YOLO 检测每个采样帧中的目标 | 置信度阈值可配置，默认 0.35 |
| 5 | 精彩度评分 | 计算目标数量、画面变化和运动强度，生成综合精彩分数 | 评分公式可解释，包含目标密度和画面变化 |
| 6 | 片段筛选 | 按分数筛选关键帧，避免同一时间段重复选择 | 返回 TOP N 个精彩片段 |
| 7 | 证据帧保存 | 保存精彩片段的证据帧图片 | 最多保存 3 个证据帧 |
| 8 | 关键帧审核 | 支持人工对关键帧执行保留或忽略 | 支持 keep/ignore 操作 |
| 9 | 分析报告 | 输出关键帧联系表、分析报告和视频文件 | 报告包含视频信息、精彩片段、关键帧 |
| 10 | 历史任务 | 任务完成后能够从历史记录重新打开并继续审核 | 重启服务后任务依然存在 |

### 3.2 推荐评分规则

```
highlight_score =
    object_score * 0.45
  + scene_change_score * 0.35
  + motion_score * 0.20
```

| 指标 | 含义 |
|---|---|
| `object_score` | 当前采样帧检测到的目标数量归一化分数 |
| `scene_change_score` | 当前帧与相邻采样帧的画面差异 |
| `motion_score` | 画面运动强度或连续帧变化程度 |
| `highlight_score` | 三项指标加权后的最终推荐分数 |

## 四、任务状态流转

```
created -> queued -> running -> completed
                              └-> failed
```

### 4.1 状态说明

| 状态 | 说明 |
|---|---|
| created | 任务已创建，等待分析 |
| queued | 任务已加入分析队列 |
| running | 任务正在分析中 |
| completed | 分析完成 |
| failed | 分析失败 |

## 五、API 接口约定

### 5.1 公共接口

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/health` | 服务与 OpenCV 可用性检查 |
| POST | `/api/jobs` | 上传视频并创建任务 |
| GET | `/api/jobs` | 获取历史任务列表 |
| GET | `/api/jobs/<job_id>` | 查询一个任务状态 |
| DELETE | `/api/jobs/<job_id>` | 删除未运行任务 |

### 5.2 方向 B 接口

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/api/jobs/<job_id>/analyze` | 将任务加入后台分析队列 |
| PATCH | `/api/jobs/<job_id>/review` | 保存关键帧保留/忽略、标签和备注 |
| POST | `/api/jobs/<job_id>/rough-cut` | FFmpeg 粗剪接口 |
| GET | `/api/jobs/<job_id>/report` | 读取分析报告 |
