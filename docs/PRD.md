# 智能视频精彩片段提取系统 - PRD

## 一、项目概述

### 1.1 项目名称

智能视频精彩片段提取系统

### 1.2 项目方向

方向 B：智能视频精彩片段提取系统

### 1.3 业务目标

面向游戏录屏、游戏场景演示和宣传素材，利用目标检测、画面变化和运动强度，自动找出值得人工复核的关键帧和候选片段，提升视频剪辑效率和内容质量。

### 1.4 项目背景

数字媒体内容团队每天处理大量游戏录屏和场景演示视频，人工逐段观看定位精彩片段效率低下。系统通过计算机视觉技术自动分析视频内容，筛选关键帧，生成推荐片段，减少人工工作量，提高内容产出效率。

## 三、业务场景

### 3.1 场景一：游戏录屏精彩片段提取

- **用户**：视频编辑
- **场景描述**：上传一段30分钟的游戏对战录屏，系统自动分析画面，提取出5-10分钟的精彩对战片段
- **期望结果**：获得推荐片段列表、关键帧联系表、可直接使用的粗剪视频

### 3.2 场景二：场景演示素材筛选

- **用户**：内容运营
- **场景描述**：上传多个游戏场景演示视频，批量分析后筛选出适合做宣传素材的片段
- **期望结果**：每个视频的精彩分数排名、推荐片段、可编辑的片段列表

### 3.3 场景三：历史任务重新审核

- **用户**：视频编辑
- **场景描述**：重新打开一周前的分析任务，调整片段边界或修改关键帧标签
- **期望结果**：完整的历史记录、可编辑的片段信息、重新生成的输出文件

## 四、核心流程

### 4.1 系统架构

```
用户上传视频
    -> 创建任务（返回任务ID）
    -> 任务入队等待处理
    -> 视频采样（OpenCV）
    -> YOLO目标检测
    -> 画面变化计算
    -> 运动强度分析
    -> 综合评分计算
    -> 关键帧筛选
    -> 推荐片段生成
    -> 任务完成
    -> 人工审核调整
    -> FFmpeg粗剪输出
    -> 生成报告和交付文件
```

### 4.2 任务状态流转

```
created -> queued -> running -> completed
                              └-> failed
```

### 4.3 关键帧筛选流程

```
采样帧列表
    -> 计算每帧综合分数
    -> 按分数降序排序
    -> 去除时间相近的重复高分帧
    -> 选择TOP N关键帧
    -> 生成候选片段
    -> 合并相邻片段
    -> 输出推荐片段列表
```

## 六、评分规则

### 6.1 综合评分公式

```
highlight_score =
    count_score * 0.30
  + type_score * 0.40
  + motion_score * 0.30
```

### 6.2 指标详细说明

| 指标           | 计算方法                                     | 归一化范围 | 权重   |
| ------------ | ---------------------------------------- | ----- | ---- |
| count_score  | 当前采样帧检测到的目标数量 / 5（上限1.0）              | 0-1   | 0.30 |
| type_score   | 高价值目标类别基础分 + 多高价值目标叠加分（上限1.0）           | 0-1   | 0.40 |
| motion_score | 当前帧与前一帧检测目标数量差值 × 0.15（上限1.0）         | 0-1   | 0.30 |

### 6.3 高价值目标类别

| 类别         | 基础分值 | 说明       |
| ---------- | ----- | -------- |
| person     | 0.4   | 人物角色     |
| knife      | 0.5   | 武器工具     |
| baseball bat | 0.4   | 武器工具     |
| car        | 0.3   | 交通工具     |
| motorcycle | 0.3   | 交通工具     |
| bus/truck  | 0.3   | 交通工具     |
| boat       | 0.3   | 交通工具     |
| sports ball | 0.3   | 运动道具     |
| baseball glove | 0.3 | 运动装备     |
| skateboard/surfboard | 0.3 | 运动装备 |
| tennis racket | 0.3 | 运动装备 |
| cell phone | 0.3   | 电子设备     |
| dog/cat    | 0.2   | 动物       |
| book       | 0.2   | 物品       |
| clock      | 0.1   | 物品       |

### 6.4 参数配置

```json
{
  "sampling_interval": 15,
  "top_n_segments": 5,
  "segment_min_duration": 2.0,
  "segment_max_duration": 10.0,
  "confidence_threshold": 0.35,
  "weight_object_count": 0.30,
  "weight_object_type": 0.40,
  "weight_motion": 0.30
}
```

## 七、片段边界规则

### 7.1 边界约束

```
0 <= start < end <= video_duration
```

### 7.2 边界场景处理

| 场景               | 处理策略                 |
| ---------------- | -------------------- |
| 最高分关键帧靠近视频开头     | 从视频开头到关键帧后N秒作为片段起始   |
| 最高分关键帧靠近视频结尾     | 从关键帧前N秒到视频结尾作为片段结束   |
| 用户设置的目标时长大于原视频时长 | 输出完整原视频，并给出提示        |
| 视频没有音频轨道         | 正常处理视频流，输出无音频视频，给出提示 |
| 关键帧数量不足          | 使用所有可用关键帧，合并为尽可能长的片段 |
| 连续多个高分帧来自同一个镜头   | 去重处理，保留每2秒最多1个关键帧    |

### 7.3 推荐策略目标

当源视频足够长时，推荐片段应尽量达到用户设置的目标时长，不能因为最高分关键帧靠近结尾而意外只输出几秒。
